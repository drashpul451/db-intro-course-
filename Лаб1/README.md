# Результати

## Вимоги

- Система повинна зберігати інформацію про гравців, зокрема їхній нікнейм, ім'я, прізвище, країну та дату народження.
- Система повинна зберігати інформацію про команди, включаючи назву команди, країну та тренера.
- Система повинна дозволяти менеджити склад команд
- Система повинна дозволяти створювати кіберспортивні турніри та керувати ними.
- Система повинна зберігати інформацію про матчі, включаючи дату проведення та результати
- Система повинна дозволяти переглядати інформацію про команди, гравців, турніри та результати матчів.

# Сутності

## Player

Таблиця з інформацією про гравця

| Атрибут | Опис |
|---|---|
| **PlayerID** | Ідентифікатор гравця (PK) |
| **Nickname** | Ігровий псевдонім |
| **First_name** | Ім’я гравця |
| **Last_name** | Прізвище гравця |
| **Country** | Країна яку гравець представляє |
| **Date_of_birth** | Дата народження |

### Зв'язок

**Player - Team Player (1:N/0)**

Один гравець може бути учасником багатьох команд або жодної команди

---

## Team Player

Таблиця яка зберігає інформацію про гравця як частину команди

| Атрибут | Опис |
|---|---|
| **TeamPlayerID** | Ідентифікатор гравця у команді (PK) |
| **PlayerID** | Ідентифікатор гравця, позичений з таблиці Players (FK) |
| **GameTeamID** | Ідентифікатор команди по грі, позичений з таблиці Game Team (FK) |
| **Join_date** | Дата приєднання до команди |
| **Role** | Роль у команді |

---

## Game Team

У цій таблиці зберігаються команди які представляють загальну команду у конкретній грі

| Атрибут | Опис |
|---|---|
| **GameTeamID** | Ідентифікатор команди по грі (PK) |
| **GameID** | Ідентифікатор гри, позичений з таблиці Game (FK) |
| **TeamId** | Ідентифікатор команди, позичений з таблиці Team (FK) |

### Зв'язки

**Game team - Team Player (1:N)**

У одній команді по грі має бути кілька гравців

**Game team - Match participant (1:N/0)**

Одна команда по грі є учасником багатьох або жодного матчів

**Game team - Tournament (1/0:N/0)**

# Зв'язки між сутностями

### Player → Team Player — 1:N

Один гравець може мати декілька записів у Team Player, наприклад, якщо він протягом кар'єри переходив до різних команд. Кожен запис Team Player стосується одного конкретного гравця.

### Team → Game Team — 1:N

Одна команда може мати декілька складів для різних комп'ютерних ігор. Кожен Game Team належить одній команді.

### Game → Game Team — 1:N

Одна гра може мати багато команд, які беруть участь у цій дисципліні. Кожен Game Team пов'язаний з однією грою.

### Game → Tournament — 1:N

Одна гра може мати багато турнірів. Кожен турнір проводиться для однієї конкретної гри.

### Organizer → Tournament — 1:N

Один організатор може проводити багато турнірів. Кожен турнір має одного організатора.

### Tournament → Match — 1:N

Один турнір складається з багатьох матчів. Кожен матч проводиться в рамках одного турніру.

### Match → Match Participant — 1:N

Один матч може мати декілька учасників. Кожен запис Match Participant належить одному матчу.

### Game Team → Match Participant — 1:N

Одна команда в конкретній грі може брати участь у багатьох матчах. Кожен запис Match Participant відповідає одній команді.

### Game Team → Team Player — 1:N

Один склад команди в конкретній грі може містити багато гравців. Кожен запис Team Player відповідає одному гравцю в одному складі.

# Припущення / обмеження

- Один турнір присвячений одній грі. (Tурнір може проводитися для CS2, Dota 2 і тд.)
- Одна команда може брати участь у багатьох турнірах.
- Один організатор може організовувати декілька турнірів.
- Турнір складається з одного або декількох матчів.
- Матч мусть мати декілька учасників-команд.
- Prize можу бути будь яким видом призу, як грошима, так і іншими.
- Переможцем турніру може бути лише команда, яка брала участь у цьому турнірі. (треба зробити перевіркою)
- Система призначена для зберігання та управління інформацією про турніри, а не для проведення самих матчів у реальному часі.
- У кожному турнірі та матчі може бути лише один переможець.
